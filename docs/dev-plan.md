# 개발 계획서

기획안([planning.md](planning.md))을 실제로 만드는 순서와 구조입니다. 결정 근거는 [decisions.md](decisions.md)에 있습니다.

## 1. 목표와 성공 기준

기획안의 성공 기준을 그대로 개발 목표로 씁니다.

- 고객 정보와 녹음(또는 전사 텍스트)을 보내면 Notion 고객 보드에 `확인 대기`로 등록된다.
- 가상 상담 10건 중 9건 이상에서 핵심 정보(이름, 연락처, 이메일, 행사 종류, 희망 일시, 지역, 예산, 요청 사항, 다음 연락 시점)가 정확하다.
- 기존 고객의 새 상담은 이전 이력을 지우지 않고 추가된다.
- 확인·수정이 건당 5분 이내다(실사용 테스트에서 측정).

## 2. 구조

```
[친구] 녹음 파일 + 캡션(성함/연락처/이메일)  또는  전사 텍스트(txt/srt/vtt)
        │  텔레그램 사각사각 봇
        ▼
[Hermes gateway → profile `sagak`]  STT 자동 전사는 끔 → 파일 경로를 에이전트에 전달
        │
        ├─ 전사      src/sagak/transcribe.py  전용 STT, 구간별 시간 포함 (텍스트 입력이면 건너뜀)
        ├─ 추출      LLM이 정해진 JSON 스키마로 추출 (근거 문장·시간·확인 필요 표시)
        ├─ 검증      src/sagak/validate.py   스키마 검사, 전화번호 정규화
        └─ 기록      src/sagak/notion_sync.py 고객 DB 갱신 + 상담 이력 DB 추가 (규칙은 코드로 강제)
        ▼
텔레그램으로 결과 요약 + Notion 링크
```

- 판단(추출)은 LLM, 기록과 규칙 검사는 코드가 맡는다. 데이터 처리 규칙은 [CLAUDE.md](../CLAUDE.md) 참고.
- 고객 정보는 녹음 파일의 **캡션**으로 함께 보내 한 메시지로 묶는다. 캡션이 없으면 다시 요청한다.
- Notion은 서비스 전용 워크스페이스 `사각사각`에 `고객` DB(전화번호가 고유 키)와 `상담 이력` DB(고객 relation)를 둔다.

## 3. 개발 환경

| 단계 | 환경 | 비고 |
|---|---|---|
| 개발 | 맥 네이티브 Hermes, profile `sagak` | 기존 gateway가 여러 profile을 함께 처리. 모델은 기존 OAuth 구독 로그인을 profile끼리 공유 |
| 운영 1차 | 맥을 호스트로 한 컨테이너 | named volume, 운영용 봇 분리, 스킬 쓰기 잠금. 런타임은 그때 결정 |
| 운영 2차 | 클라우드(VPS 등) | profile export로 이전, 암호화 백업 |

- **Claude 세션**: 코드, 스킬, 테스트, 문서, Notion DB 구성, 커밋을 만든다.
- **개발 봇**: 사각사각 서비스의 테스트판. 실제 형식의 녹음으로 처음부터 끝까지 확인하고 사용성을 점검한다.
- 비밀값은 Hermes 대시보드의 sagak profile에서만 입력한다.

## 4. 단계

각 단계는 확인 기준을 통과해야 다음으로 넘어갑니다.

| # | 단계 | 확인 기준 | 참고 강의 |
|---|---|---|---|
| 1 | 레포와 profile 뼈대: `sagak` profile 생성, SOUL.md, 도구 제한 | `hermes -p sagak` 실행, 불필요한 도구 꺼짐 | #1.0, #1.2, #2.1, #2.2 |
| 2 | 개발 봇 연결, 허용 사용자 지정 | 캡션 달린 녹음과 텍스트를 봇이 받아 파일 경로를 확인 | #1.1, #2.3 |
| 3 | 전사: `transcribe.py`, STT 후보 비교 | 가상 녹음에서 구간 시간 포함 전사 생성 | #1.4 |
| 4 | 추출과 검증: 스키마, `validate.py` | 가상 10건 단위 테스트 통과 | #1.2 |
| 5 | Notion 기록: DB 생성, `notion_sync.py` | 신규·기존 고객, 후보 표시, 덮어쓰기 금지 테스트 통과 | — |
| 6 | 처음부터 끝까지 검증 | 개발 봇으로 10건 중 9건 정확 | #1.6 |
| 7 | 운영 1차: 컨테이너, 운영 봇, 스킬 쓰기 잠금 | 재시작 후 자동 복구, 데이터 유지 | #3.2, #3.3 |
| 8 | 운영 안정화: profile export 이전, 백업 | 다른 환경에서 복원 성공 | #3.4~#3.6 |

이후 확장(범위 밖): 확인 대기 알림(cron, #1.7), 웹 업로드 입력(#4), 고객사별 로그인·구독 연결.

## 5. 향후 서비스를 위한 대비

- 고객사 1곳 = Hermes profile 1개. 고객사마다 다른 값(Notion DB ID, 모델, 봇 토큰)은 코드에 넣지 않는다.
- 개인 구독(OAuth)을 다른 고객의 서비스에 쓰려면 각 제공사 약관 확인이 필요하다. 기본은 고객사별 API 키.

## 6. 열려 있는 항목

- STT 서비스 최종 선택(가상 녹음 비교 후)
- 컨테이너 런타임(운영 1차 시점)
- 실제 상담량·소요 시간·관리 항목(클라이언트 확인)
